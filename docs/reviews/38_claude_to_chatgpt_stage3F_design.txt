PART A - comparing candidate moves (Version 14)

1. Command: "compare N <m1> <m2> [<m3> ... <m6>]" - 2 to 6 legal moves of
   the side to move S, written like e2e4 or e7e8q; N = the depth used for
   the bounded parts (loop plies and exchange captures; 1..5). Nothing is
   played; the board, turn, history and memory stay unchanged.

2. For each candidate, its raw facts, taken ONLY from existing reports
   (no new measurement):
   R (3A)      COUNT both sides: U1 U2 U3 GAINED RESTORED OPENED; CHECK;
               MATE1 for each side; PROTECT+/- and ATTACK+/- counts.
   replies (3B) THREAT (mover's mate-in-one moves after m) and SUMMARY
               REPLIES n STOPS LEAVES NO-THREAT ALLOWS.
   loop (3C)   the first-move line for m at depth N: FORCED / POSSIBLE k
               OF r / NOT-FOUND, MATED White n Black n, LIMIT.
   goal (3D)   only if a goal is active: REAL depth N result for m per goal
               square (CONDITION IF FORCED / IF POSSIBLE k OF r / ELSE).
   3E          capture: TAKES type VALUE v, SQUARES d, MATERIAL FORCED /
               POSSIBLE NONNEGATIVE / -, BOUNDED; the ORDER group (1 or 2).
   Printed as:
     CANDIDATE <m>
     FACT <name> <value>          one line per fact, fixed order and names
   Example names: R-COUNT-WHITE, R-COUNT-BLACK, CHECK, MATE1-White,
   REPLIES, LOOP, GOAL-f7-REACH, CAPTURE, MATERIAL, SQUARES, GROUP.

3. Comparison of each pair of candidates, fact by fact:
     COMPARE <fact> <m1> <value1> <m2> <value2> SAME | DIFFERENT
   and, only for facts where an earlier approved stage already defines a
   direction for S (no new direction is introduced):
     loop result      FORCED > POSSIBLE > NOT-FOUND (mate of the other side)
     goal REAL result IF FORCED > IF POSSIBLE > ELSE
     MATERIAL class   FORCED > POSSIBLE > none
     threat           stops / leaves as in 3B (for the mover: a mate-in-one
                      threat present vs none)
   the line adds AHEAD <m> or TIE. For counts (U1, U2, ...) no direction is
   assigned: only SAME / DIFFERENT and the two numbers ("more pieces that
   can't move" is not called better or worse for either side).

3b. The owner's IF chains (added at the owner's request, 2026-10-25; his
   words: "you meand the value of the chesspieces if condition and the
   moved squares if condition?"). Each candidate also shows its place in
   the owner's orders, all already approved:
     VALUE-ORDER   the captured piece's value and its label in the value
                   chain (ideas 5-8; greatest = IF ... smallest = ELSE),
                   or "none" for a non-capture;
     SQUARES-ORDER the squares travelled and its label in the distance
                   chain (idea 4; fewest = IF ... most = ELSE);
     GROUP         its place in the combined list of idea 7 (group 1
                   CAPTURE or group 2 DISTANCE, with the label there).
   The labels are computed exactly as "order N" computes them for the
   current position (the chains run over all legal moves of S, so the
   labels are the same as in "order N"). In the pair comparison these
   lines say SAME / DIFFERENT and EARLIER-IN-ORDER <m> (the candidate that
   comes first in the owner's list) - never AHEAD and never "better",
   because an order is a measurement, not a judgement (reviews 17, 27, 29).
   They take no part in the AGREEMENT rule of step 4.
   Example (E-B rook position): d1d5 and e4d5 both VALUE-ORDER R 5 IF
   (SAME); SQUARES-ORDER 4 vs 1 (DIFFERENT, EARLIER-IN-ORDER e4d5);
   MATERIAL POSSIBLE vs FORCED (AHEAD e4d5).

4. Agreement and disagreement among measurements, per pair:
     AGREEMENT <m1> <m2> ALL-AHEAD <m> | MIXED | ALL-TIE
   ALL-AHEAD when every directed fact is AHEAD for the same candidate or
   TIE; MIXED when directed facts point to different candidates (an
   incomparable pair - kept, never resolved by weights); ALL-TIE when all
   directed facts tie. Undirected facts are listed, never counted.

5. Bounded uncertainty: every fact computed with a limit carries it (LIMIT
   N, BOUNDED); a line "UNCERTAIN <m> <fact> beyond depth N" when the
   search was cut. FORCED and POSSIBLE are never merged.

6. Output frame and order:
     COMPARE BEGIN <S> DEPTH <N> CANDIDATES <m1> ... <mk>
     NOTE measurements only: no weights, no move is chosen or played
     CANDIDATE blocks in the order typed; then COMPARE lines for each pair
     (m1-m2, m1-m3, ... in typed order), facts in the fixed order; then
     AGREEMENT lines; COMPARE END.

7. Tests (as review 37 asks), all with hand-checked expected values:
   - E3 position: candidates d1h5, d1f3, g1f3 (3B and 3C facts: Qh5 THREAT
     h5f7, POSSIBLE 20 OF 28 at depth 3; Qf3 POSSIBLE 21 OF 31; Nf3 no
     threat, NOT-FOUND) - AHEAD lines and MIXED / ALL-AHEAD as computed.
   - A higher capture value with a less favorable bounded material result:
     the E-B rook position with an added black pawn, so that one capture
     takes the rook (5) but is only POSSIBLE and another takes a pawn (1)
     and is FORCED - MATERIAL AHEAD goes to the lower-value capture, and
     CAPTURE values are only listed.
   - Ties (two quiet moves with the same directed facts: ALL-TIE) and an
     incomparable pair (MIXED).
   - Determinism, invariants, refused input (fewer than 2 or more than 6
     candidates, illegal or repeated moves, bad depth), all earlier
     transcripts unchanged.
