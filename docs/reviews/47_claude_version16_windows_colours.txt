The colour codes were printed as text ("←" is how the Windows console

FIRST FIX — DID NOT WORK
  Version 15 (the beginner rewrite) had removed version 14's lines
    #ifdef _WIN32
        if (_isatty(0)) { (void)system("chcp 65001 > nul"); }
    #endif
  and Claude's check (docs/reviews/45, Part B item 3) had called them "not
  needed". Claude first put them back, believing that starting cmd.exe
  also switches the console to show colours. The owner's run showed the
  codes as text again. So that belief was wrong (or does not hold on the
  owner's Windows), and Claude's earlier statement in review 45 is
  superseded by this record. That first fix was never pushed.

SECOND FIX — VERSION 16 AS PUSHED
  A new function enable_console_colours(), called in main() before the
  first output (after the chcp lines):
    - on Windows: GetStdHandle(STD_OUTPUT_HANDLE), GetConsoleMode, then
      SetConsoleMode(... | ENABLE_VIRTUAL_TERMINAL_PROCESSING). This is the
      documented Windows way for a program to have "\033[...m" colour codes
      shown as colours. If the output is not a console (a file, as in the
      tests), GetConsoleMode fails and nothing changes.
    - on other systems: does nothing.
  windows.h is included on Windows only, with WIN32_LEAN_AND_MEAN.
  Version 14's chcp lines are kept (UTF-8 code page; harmless; the
  _isatty check protects redirected input).
